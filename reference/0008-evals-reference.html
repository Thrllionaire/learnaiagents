Vocabulary

From Demystifying evals for AI agents (quoted):

Task“A single test with defined inputs and success criteria.”
Trial“Each attempt at a task.” Run several, because outputs vary.
Transcript“The complete record of a trial, including outputs, tool calls, reasoning, intermediate results.”
Outcome“The final state in the environment at the end of the trial.”
Grader“Logic that scores some aspect of the agent's performance.” One task, many graders.
Eval harnessRuns tasks, records every step, grades, aggregates.

Two metrics

pass^kAll k pass pkGuardrails; anything user-facing

Examples: 0.753 ≈ 42%. 0.95 ≈ 59%.

Checklist: before you trust the number

  1. Read transcripts first. Graders come from failures you saw, not ones you imagined (Husain).
  2. Isolate trials. Fresh environment each time; “leftover files, cached data” cause correlated failures.
  3. Balance the set. Include cases where the behaviour should happen, or a do-nothing agent scores 100%.
  4. Watch it fail. Every grader gets a hand-built failing input. A grader only ever seen passing hasn't been tested.
  5. Check the label. Does the metric measure the layer its name claims? Behind a gate, outcome = gate.
  6. Suspect the task first. “A 0% pass rate across many trials… is most often a signal of a broken task, not an incapable agent.”
  7. Report k. “5/5” and “1/1” are different claims. Always say how many trials.
  8. Unambiguous tasks. “Two domain experts would independently reach the same pass/fail verdict.”

Capability vs regression

Capability evals “should start at a low pass rate”. They measure what you're trying to make possible. Regression evals “should have a nearly 100% pass rate”, and any drop is a signal. Today's legit-delete and control tasks are regression-shaped. inj-polite's transcript grader is capability-shaped.
