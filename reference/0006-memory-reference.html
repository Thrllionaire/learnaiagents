Memory Tool Reference

The command set, the error strings, and the security checklist for a client-side memory handler. Print it and keep it next to the tool surface card.

Within-session vs. cross-session

Lives inDies when…
Within-session
messages		 RAM, inside one process The process exits — compaction and trimming (Lesson 05) manage this state's size, not its lifetime
Cross-session
a memory file		 Disk (or any store you own) outside the process You never wrote it anywhere durable — not when the process exits
Enabling it

One line, no schema — it's an Anthropic-provided tool:

tools=[{"type": "memory_20250818", "name": "memory"}]

It's client-side: Claude only ever requests an operation. Your handler executes it against storage you own and returns a tool_result — the ordinary tool-use loop from Lessons 03–04, applied to files.

Commands

CommandRequired fieldsSuccess stringNotable error
view path (+ optional view_range) Directory listing, or 1-indexed tab-separated file contents "The path {path} does not exist. Please provide a valid path."
create path, file_text "File created successfully at: {path}" Overwrite-vs-error on an existing path is your choice — both are valid
str_replace path, old_str (+ optional new_str) "The memory file has been edited." Zero or multiple matches of old_str is an error, never a silent replace-all
insert path, insert_line, insert_text "The file {path} has been edited." "Invalid `insert_line` parameter: {n}. It should be within the range [0, {n_lines}]"
delete path "Successfully deleted {path}" Must refuse a path that resolves to the memory root itself
rename old_path, new_path "Successfully renamed {old_path} to {new_path}" "Error: The destination {new_path} already exists" — never overwrite on rename

Security checklist

  • Path traversal. /memories/../../secrets.env is a real request, not a hypothetical. Resolve every path to its canonical absolute form and check containment under the memory root — never strip a string prefix and trust what's left.
  • The root itself. delete and rename must both refuse to touch the memory root directory, not just files inside it.
  • Sensitive data. Claude usually declines to write secrets to memory on its own; don't rely on that alone — validate and strip before your handler writes.
  • Size and expiry. Cap file size, cap what a single view returns (page the rest via view_range), and expire files nothing has touched in a long time.

Pairs with, doesn't replace, Lesson 05

Compaction and memory answer different questions. Compaction: is the current window too big? Memory: will this process still exist when the answer matters? A long-running agent needs both — memory for what must outlive a session, compaction so a single session doesn't blow its window before anything gets written down.
