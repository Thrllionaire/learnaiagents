Agent Loop Cheat Sheet

The shapes, the invariants, and the current model IDs, for when you are writing the loop and need the exact form rather than the explanation.

Reference 01· Python + Anthropic SDK· Verified 2026-09-19

Skeleton

messages = [{"role": "user", "content": user_input}]

while True:
    response = client.messages.create(
        model="claude-opus-5", max_tokens=16000,
        tools=TOOL_SCHEMAS, messages=messages,
    )
    if response.stop_reason != "tool_use":
        break
    messages.append({"role": "assistant", "content": response.content})
    messages.append({"role": "user", "content": [
        {"type": "tool_result", "tool_use_id": b.id,
         "content": TOOLS[b.name](**b.input)}
        for b in response.content if b.type == "tool_use"
    ]})

Guard before reading

Check stop_reason before touching response.content. A refusal returns HTTP 200 with a stop_reason of "refusal", not an exception. Code that assumes a text block is present will throw on the next().

Roles: provenance, not semantics

The Messages API has two conversational roles. A role records who generated the tokens, not what kind of content it is. Content type lives on the block.

RoleHoldsTrust
assistant Only what the model itself generated: text, tool_use, thinking n/a (its own output)
user Everything from outside the model: the human's text and tool_result blocks Untrusted
system
(top-level)		 Operator instructions, fixed before the run Trusted
system
(in messages[])		 Operator instructions added mid-run. Not on Sonnet 5; no beta header Trusted — the injection-safe operator channel

There is no tool role. A tool result was produced by your harness, not the model, so it is user-role content carrying a tool_result block. The model is not confused about what it is: the block type and the tool_use_id identify it. The role governs turn-taking; the block type governs meaning.

The security consequence

Tool results land in the same trust channel as user input. Text fetched from a web page, a database row, or a file arrives at user-level trust and sits below the system prompt. This is the primary prompt-injection vector in agents, and it falls straight out of the role model. Treat every tool_result as hostile input.

Contrast: OpenAI's API has a tool role with a tool_call_id. Functionally near-identical (both bind results to requests by ID), but the separate role implies tool output is its own trust tier. It is not.

Invariants: break these and it fails

  1. Append response.content verbatim. Never response.text, never a reconstructed list.
  2. Every tool_result carries the tool_use_id of the block that requested it.
  3. All results from one assistant turn go in one user message. Splitting them suppresses parallel tool calling.
  4. A failed tool still returns a tool_result, with "is_error": True. Never silently drop one; the ids must balance.
  5. The transcript is re-sent in full every iteration. Cost grows with the square of run length.
  6. Continue on "tool_use" only. Treat every other stop_reason as an exit.
