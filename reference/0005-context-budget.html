The rule underneath both

"Good context engineering means finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome." Same instinct as Lesson 03's tool results, scaled to the whole window: prompt, schemas, messages, everything.

They compose. A long-running coding agent plausibly uses all four at once: notes for decisions made hours ago, compaction when a session nears its limit, sub-agents for isolated investigations, just-in-time retrieval so the whole codebase is never loaded at once.

Quick disambiguation

  • Compaction vs. notes: compaction is reactive — it fires because the window is full. Notes are proactive — written because you know a reset is coming, before the window is anywhere near full.
  • Sub-agents vs. just-in-time retrieval: sub-agents isolate a messy process (search, exploration) so its noise never reaches the parent. JIT retrieval defers loading a known record until a tool call actually needs it. One hides work; the other delays a fetch.
  • Compaction vs. restart: compaction keeps the run going with a summary in place of history. A restart from zero throws away everything, including facts nothing else captured — the more expensive failure, and the reason checkpointing matters on long runs.
